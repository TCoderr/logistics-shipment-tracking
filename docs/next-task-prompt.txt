------------------------------------------------------------------------------
1. AMAÇ
------------------------------------------------------------------------------
Operasyon görevlisi bir gönderi oluşturur. Ağ hatası yüzünden yanıtı alamasa bile
aynı Idempotency-Key ile tekrar denediğinde ikinci gönderi oluşmaz ve ilk yanıtın
aynısını alır. Yetkili kullanıcılar gönderi detayını görür; hub görevlisi yalnız
kendi hub'ıyla ilişkili gönderileri görebilir, diğerleri için 404 alır.

------------------------------------------------------------------------------
2. TEKNİK KARARLAR (değiştirme; değişmesi gerekirse gerekçeyle raporla)
------------------------------------------------------------------------------
- .NET 10 (net10.0), ASP.NET Core Minimal API, EF Core 10.0.x,
  Npgsql.EntityFrameworkCore.PostgreSQL 10.0.x (EF Core ile aynı major).
- PostgreSQL 18. Tek LogisticsDbContext (Lst.Platform içinde), modül başına şema:
  shipments, operations, identity, platform. snake_case adlandırma
  (EFCore.NamingConventions'ın EF Core 10 uyumlu sürümü yoksa elle konvansiyon).
- Enum'lar varchar(32) + CHECK constraint. Zamanlar timestamptz (UTC).
  İş tarihi Europe/Istanbul.
- Concurrency token: PostgreSQL xmin (shipments).
- Generic repository YOK, MediatR YOK, event sourcing YOK. Handler'lar
  DbContext'i doğrudan kullanır. Domain katmanı EF Core/ASP.NET'e referans vermez.
- Kimlik doğrulama: ASP.NET Core Identity + cookie (__Host-lst.auth, HttpOnly,
  Secure, SameSite=Strict), antiforgery (X-CSRF-TOKEN). JWT yok.
  API isteklerinde yönlendirme yerine 401/403 ProblemDetails.
- Hata biçimi: RFC 9457 ProblemDetails, type = "urn:lst:problem:<code>",
  "code" ve "traceId" uzantıları.
- Saat: TimeProvider (testte FakeTimeProvider). Id: Guid.CreateVersion7().
- OpenAPI: Microsoft.AspNetCore.OpenApi (yalnız Development'ta yayınlanır).
- Log: ILogger + JSON console. Ad, telefon, e-posta, adres, public tracking kodu,
  istek gövdesi LOGLANMAZ.

4. KAPSAM — DAHİL
------------------------------------------------------------------------------
4.1 Tablolar (docs/04-database-design.md'deki tanımlarla; yalnız aşağıdaki kolonlar)
  operations.hubs: id, code (^[A-Z]{3}-[0-9]{2}$, unique), name, city, district,
    is_active, created_at. Seed (migration veya Development seed): IST-01 İstanbul,
    ANK-02 Ankara, IZM-01 İzmir (aktif), BRS-01 Bursa (pasif).
  identity.*: ASP.NET Core Identity tabloları (uuid anahtar) +
    identity.user_hub_assignments (user_id, hub_id, assigned_at,
    assigned_by_user_id, PK(user_id, hub_id)).
  shipments.shipments: id, tracking_number (^LS[0-9]{10}$, unique),
    public_tracking_code (26, unique), kind ('Forward' varsayılan; CHECK
    Forward/Return), external_reference (null, unique DEĞİL), service_level,
    status (9 değerlik CHECK; bu dilimde yalnız 'Created' yazılır),
    status_occurred_at, status_changed_at, origin_hub_id, destination_hub_id,
    current_hub_id (null), package_count (1..20), promised_delivery_date (date),
    delivery_attempt_count (0), declared_value_amount numeric(12,2) null,
    declared_value_currency char(3) null (ikisi birlikte null/dolu CHECK),
    created_at, created_by_user_id, updated_at, xmin.
  shipments.shipment_parties: PK(shipment_id, role Sender|Recipient), full_name,
    company_name, phone_e164 (CHECK ^\+[1-9][0-9]{7,14}$), phone_last4, email,
    address_line1, address_line2, district, city, postal_code, country_code.
  shipments.packages: id, shipment_id, sequence (1..20), label_code (unique,
    "{trackingNumber}-{sequence:00}"), weight_grams (1..70000), length_mm,
    width_mm, height_mm (1..3000), content_description. UNIQUE(shipment_id, sequence).
  shipments.tracking_events: docs/04 §3.5'teki kolonlar (carrier_event_receipt_id
    kolonu FK'siz; carrier tablosu sonraki dilimde). Bu dilimde yalnız
    event_type='Created', source='Operator', outcome='Applied' yazılır.
  platform.idempotency_records: docs/04 §3.12'deki gibi; UNIQUE(actor_scope,
    endpoint, idempotency_key); expires_at = created_at + 48 saat.
  platform.audit_entries: docs/04 §3.14'teki gibi; changes alanında PII yok.

4.2 Domain kuralları
  - TrackingNumber: "LS" + 9 rastgele rakam (RandomNumberGenerator) + Luhn
    kontrol hanesi. Unique ihlalinde en fazla 3 kez yeniden üret.
  - PublicTrackingCode: 16 bayt CSPRNG → Crockford Base32 (26 karakter).
  - PromisedDeliveryDate (Europe/Istanbul): kesim 15:00; sonrası veya iş günü
    dışı → kabul günü sonraki iş günü. İş günü Pzt–Cmt; tatiller konfigürasyon
    listesinden (Sla:Holidays). Standard = kabul + 2 iş günü, Express = +1.
  - Doğrulama: 1–20 paket; ağırlık 1–70000 g; kenarlar 1–3000 mm; telefon E.164;
    TR posta kodu 5 hane; city ve line1 zorunlu; externalReference ≤ 64;
    declaredValue ikisi birlikte; origin ve destination aktif hub olmalı
    (bilinmeyen → 422 unknown-hub, pasif → 422 hub-inactive).
  - Yeni gönderi: status=Created, status_occurred_at=status_changed_at=now,
    tracking_events'e 'Created' olayı, audit 'ShipmentCreated'.

4.3 Endpoint'ler
  E1  POST /api/auth/login {userName, password} → 204 + cookie
      POST /api/auth/logout → 204
      GET  /api/auth/me → {id, displayName, roles[], hubCodes[], csrfToken}
  E2  POST /api/shipments   (roller: OpsAgent, OpsManager)
      İstek/yanıt örneği: docs/05-api-and-event-contracts.md §4.1.
      201 Created + Location + ETag; yanıt gövdesi PII İÇERMEZ (id,
      trackingNumber, publicTrackingCode, status, serviceLevel,
      promisedDeliveryDate, packages[{id, sequence, labelCode}], createdAt).
  E3  GET /api/shipments/{id}   (OpsAgent, OpsManager, HubOperator-kapsamlı)
      docs/05 §4.2 biçimi; bu dilimde timeline yalnız 'Created',
      openExceptions = [], allowedActions = [] (iptal dilim 4'te eklenir).
      ETag header.
      HubOperator: gönderinin origin/destination/current hub'ı kullanıcının
      atandığı hub'lardan biri değilse 404. Alıcı telefonu HubOperator için
      maskeli (+90532*****67); OpsAgent/OpsManager tam görür.

4.4 Idempotency contract'ı (docs/05 §3)
  - Idempotency-Key header zorunlu (16–128, [A-Za-z0-9_-]); yoksa 400
    idempotency-key-required, biçim hatalıysa 400 idempotency-key-invalid.
  - Kapsam: actor_scope = "user:{userId}", endpoint = "POST /api/shipments".
  - request_sha256 = SHA-256(method + "\n" + route şablonu + "\n" + gövdenin
    RFC 8785 (JCS) kanonik JSON'u). Alan sırası/boşluk farkı aynı hash vermeli.
    JCS için olgun bir kütüphane yoksa sayı ve string kurallarını kapsayan küçük,
    test edilmiş bir uygulama yaz ve sınırlarını belgeye not et.
  - Aynı transaction: SET LOCAL lock_timeout='5s' → idempotency INSERT →
    gönderi + parties + packages + tracking event + audit → idempotency
    yanıt alanlarını güncelle → COMMIT.
  - Unique ihlali → kaydı oku: hash aynı → saklanan status/gövde/Location/ETag
    ile yanıt + "Idempotency-Replayed: true"; hash farklı → 422
    idempotency-key-reused. lock_timeout aşımı → 409
    idempotency-request-in-progress + Retry-After: 1.
  - Yalnız 2xx yanıtlar saklanır; doğrulama/iş hatasında transaction rollback.
  - EF Core retry execution strategy bu transaction'da KULLANILMAZ.
  - Süresi dolmuş kayıtların silinmesi bu dilimde yok (sorgu expires_at > now
    koşulunu kullanır; süresi dolmuş kayıt bulunursa aynı transaction'da silinip
    yeni claim yapılır).

Unit testler (en az):
  U1  Üretilen 10 000 tracking number biçime uyar ve Luhn geçerlidir.
  U2  Public kod 26 karakter, yalnız Crockford alfabesi.
  U3  SLA (Cumartesi iş günü, Pazar değil): Cuma 14:59 Standard → Pazartesi;
      Cuma 15:01 Standard → Salı (kabul Cumartesi); Pazar 10:00 Express → Salı
      (kabul Pazartesi); Cumartesi 10:00 Express → Pazartesi; konfigüre edilmiş
      tatil atlanır. (Tarihleri testte somut ver, ör. Cuma = 2026-10-09.)
  U4  Kanonik hash: alan sırası/boşluk farkı aynı; değer farkı farklı hash.
  U5  Telefon maskeleme: +905321234567 → +90532*****67.
  U6  Mimari: Lst.Modules.Shipments Domain namespace'i
      Microsoft.EntityFrameworkCore ve Microsoft.AspNetCore'a bağımlı değil.

Integration testleri (gerçek PostgreSQL 18):
  I1  (D1) Geçerli istek → 201; aynı anahtar + aynı gövde (alan sırası farklı)
      → aynı gövde ve Location, Idempotency-Replayed: true; DB'de 1 gönderi,
      2 paket, 1 'Created' olayı, 1 audit kaydı.
  I2  (D2) Aynı anahtar + farklı gövde → 422 idempotency-key-reused.
  I3  (D3) Aynı anahtarla 10 paralel istek → DB'de tam 1 gönderi; başarılı
      yanıtların hepsi aynı id; diğerleri yalnız 409 in-progress olabilir.
  I4  (D4) İki farklı kullanıcı aynı anahtar → 2 ayrı gönderi.
  I5  (D5) İlk istek 400 (geçersiz telefon); düzeltilmiş gövde aynı anahtarla → 201.
  I6  (D6) expires_at geçmiş kayıt (FakeTimeProvider) → aynı anahtar yeni
      gönderi oluşturur.
  I7  (R1) Audit yazımında zorla hata (test hook) → gönderi, paket, olay ve
      idempotency kaydı yok.
  I8  Idempotency-Key yok → 400 idempotency-key-required; bilinmeyen hub →
      422 unknown-hub; pasif hub → 422 hub-inactive; 21 paket → 400 validation

  I10 HubOperator POST /api/shipments → 403.
  I11 (A2) hub.izm, IST-01→ANK-02 gönderisinin detayını → 404;

  I13 (P6) idempotency_records.response_body alıcı/gönderen adı, telefonu,

  I14 (P5) Test log sink'inde seed edilen ad/telefon/adres dizeleri geçmez.
  I15 DB kısıtları: tracking_number biçim CHECK'i, packages (shipment_id,
